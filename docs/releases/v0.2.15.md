# T1000 0.2.15 — Codex composer and production-control hardening

## Release decision

This release is accepted only when the exact clean source commit, two byte-identical builds, content-addressed managed installation, exact 0.2.14 rollback, identical 0.2.15 reinstall, graceful GUI-only activation, selected-installed-site validation, and live-authority comparison all pass.

## Core invariants

```text
payload first grid = VTE = tmux pane = tmux window = control stream
```

```text
pane root -> outer bwrap -> inner bwrap session leader -> private Codex witness
```

```text
signal = SIGWINCH only
terminal input = none
payload restart/termination = none
```

On capable kernels, signal authority is the pidfd of the exact private witness. A finite coalescing dispatcher keeps procfs/pidfd work off the ordered pane input and replay worker. Setup repair retains bounded barriers before authoritative capture.

## Five sequential improvement rounds

1. Recover and validate the inherited exact-grid, observer, and validation candidate; identify the remaining identity, topology, pidfd, ordered-worker, and selected-package gaps.
2. Bind resize admission to the exact TermDeck outer/inner containment graph and closed private launch tuple.
3. Pin signal commit to the private Codex witness with pidfd-backed liveness and fail-closed fallback rules.
4. Add bounded asynchronous dispatch and a canonical selected-package contained-composer smoke; repair harness semantics and prove no disposable residue.
5. Version, clean-commit validate, build reproducibly, publish privately, install/rollback/reinstall, activate gracefully, and verify the installed/live runtime.

## Preserved functionality

The release retains terminal byte and Unicode fidelity, tmux control framing, scroll/selection/clipboard behavior, first-key delivery, window/tab restoration, hidden recipe startup, exact Codex recovery, per-tab `CODEX_HOME`/authentication isolation, persistent tmux payloads, SQLite semantics, immutable release verification, and historical rollback.

## Residual constraints

- containment signaling requires Linux procfs; unsupported platforms fail closed;
- kernels without pidfds use the complete commit-time userspace revalidation fallback;
- validation receipts include timestamps and private runtime names and are evidentiary rather than byte-reproducible; the source commit, wheel, manifest, release ID, and remote tag are reproducible identities.
