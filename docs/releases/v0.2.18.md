# T1000 0.2.18

Release date: 22 August 2026

## Decision

Promote 0.2.18 only when the exact committed, pushed, tested, built, installed, and running source identity is the same and live tmux payload identities remain unchanged.

## User-visible changes

- OpenCode composer text remains editable until the user explicitly submits it; no parent-window fallback injects a duplicate byte or Enter.
- Plain `Ctrl+L` reaches the focused terminal application and triggers its own redraw.
- Physical wheel and the persistent per-tab scrollbar move both upward and downward through mouse-aware alternate-screen application history and return to the live bottom.
- Bracketed-paste mode survives attach/replay, so multiline text is one protected composer transaction rather than a sequence of commands.
- Composer geometry remains complete across initial attach, resize, scroll, tab switch, replay, and GUI restart.
- A false pane-dead notification is a verified no-op. Contradictory live `recovery-pending`, `missing`, or `start-error` rows are corrected without replacing the pane or process.

## Preserved contracts

- No existing OpenCode model selection is changed. Tabs manually using `opencode/x-preview-f-free` retain it; other tabs are not rewritten.
- No live OpenCode, Claude, Codex, shell, or generic process is mass-restarted.
- Clean payload exit returns to a shell in the same tab; explicit Kill remains terminal.
- Killed-terminal history remains durable until explicit Remove.
- Generic non-Codex sessions retain digest-bound recipes, all-window restoration, and fail-closed corrupt/manual/external boundaries.
- The SQLite schema is unchanged. The migration boundary remains compatible with retained 0.2.11-0.2.17 rollback releases.

## Root causes closed

1. Window-level first-key routing could overlap focused VTE delivery.
2. Positive scroll was classified as a live-edge no-op before alternate-screen mouse ownership was queried.
3. Persistent scrollbar work called a GTK-owned SQLite connection from a background worker and silently reverted on failure.
4. Plain `Ctrl+L` was intentionally swallowed by T1000 instead of remaining application-owned.
5. Pane replay required unsupported tmux `#{focus_flag}` output, causing a field-count mismatch and perpetual pre-ready setup retries.
6. Live pane-dead races were persisted as recovery errors rather than repaired as verified no-ops.

## Validation gates

- failing-first and passing unit coverage for exactly-once input, `Ctrl+L`, scroll ownership, SGR wheel encoding, virtual scrollbar depth, return-to-bottom, SQLite thread ownership, tmux mode replay, bracketed paste, and live no-op recovery;
- a real GTK/VTE/tmux alternate-screen composer smoke proving complete frames, physical and scrollbar up/down, no tmux copy mode, no auto-submit, and protected multiline paste;
- generic recovery, shell bridge, explicit lifecycle, killed history, all-window restoration, gateway refresh, and tool-independence regressions;
- complete CI and production validation with invariant source fingerprints;
- clean-commit reproducible double-build and strict artifact verification;
- managed install retaining 0.2.17 as rollback, GUI-only handoff, and post-install proof of stable tmux server/session/pane/payload identities plus corrected false-red live rows.
