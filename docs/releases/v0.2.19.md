# T1000 0.2.19

Release date: 25 August 2026

## Decision

Promote 0.2.19 only when the exact committed, pushed, tested, built, installed, and running source identity is the same and the persistent tmux server, pane identities, payload processes, working directories, model selections, conversation UUIDs, and authentication scopes remain intact across the GUI-only handoff.

## User-visible changes

- Ordinary mouse-wheel, trackpad, Page Up/Page Down, text-selection autoscroll, and the persistent scrollbar now move the actual VTE viewport. The scrollbar thumb can no longer move while terminal pixels remain frozen.
- Plain `Ctrl+L` reaches the focused terminal application exactly once and performs the application's own redraw.
- Codex/OpenCode frames are reconstructed row by row with bounded mode, SGR, wrap, cursor, and display resets. Initial attach, reattach, resize, scrolling, and opening or closing the Tabs pane no longer leave stale background rectangles, overlapping status rows, or a garbled composer.
- Opening a hidden-start Tabs pane maps its complete widget subtree before measuring or allocating it. Pulling the sidebar no longer clips its controls or corrupts the live terminal frame.
- Closing the Codex child process without closing its terminal keeps the tab in the top strip and the Tabs pane. Sidebar membership and count follow the terminal/tmux pane, not the transient foreground payload.
- Selecting a Codex authentication profile while Codex is running performs one atomic same-pane handoff: the exact conversation UUID, tmux pane, working directory, model, and terminal tab are preserved while the new private authentication binding becomes active.
- Failed authentication activation rolls back both the canonical account pointer and the terminal payload instead of displaying a selection that was never applied.
- T1000 observes the canonical system-wide Codex account source. Token or profile replacement performed outside T1000 changes the source fingerprint and is applied through the same verified same-pane handoff; per-tab private scopes do not retain stale copied credentials.
- Account changes no longer degrade into “next Codex launch”, “could not pause old terminal”, or “fresh pane did not inherit private auth environment” user workflows.
- Exact recovery discovery preserves the canonical `codex-opencode` model while remaining fail-closed. When Codex has closed its rollout descriptor, T1000 accepts only one owner-only, non-symlinked CLI rollout matching the process cwd and bounded start window; ambiguous or unverified candidates remain explicitly recoverable rather than resuming the wrong conversation.

## Preserved contracts

- Existing tmux servers, panes, Codex/OpenCode/Claude/shell payloads, model selections, working directories, and exact recovery identities are not mass-restarted.
- Each terminal retains its isolated `CODEX_HOME` selection pointer while account files and token updates remain canonical at the system source.
- An authentication change is all-or-nothing: either the new account and exact resumed payload are proven, or the previous account and payload are restored.
- Hidden, archived, and explicitly removed tabs retain their existing lifecycle semantics; only an open notebook page is protected from disappearing when its foreground child exits.
- Normal-screen history remains VTE-owned. Alternate-screen applications receive their negotiated mouse protocol only when they own that history surface.
- The SQLite schema remains compatible with retained 0.2.11–0.2.18 managed rollback releases.

## Root causes closed

1. The persistent scrollbar was bound to a virtual history coordinate while normal-screen pixels remained owned by VTE.
2. Exact-width captured rows were replayed with autowrap and inherited background styles, allowing one row to spill into the next and paint stale rectangles.
3. Sidebar show/hide paths changed geometry before the hidden subtree was mapped and before the VTE/tmux grid had reached a settled generation.
4. Sidebar membership was derived from sampled foreground-process state rather than the existence of the open terminal pane.
5. Codex account switching attempted to stop and reconstruct process trees through several non-atomic phases, exposing partial selections and “next launch” states.
6. Private authentication homes could observe a stale binding when canonical token files were replaced externally.
7. Runtime terminfo fallback performed a second synchronous inspection after the primary tool chain failed, allowing a loaded host to prevent any terminal from opening.
8. Some Codex builds close their primary rollout descriptor after startup; selecting the nearest same-cwd rollout by timestamp could silently bind an underdetermined conversation instead of failing closed.

## Validation gates

- unit coverage for native viewport ownership, selection scrolling, scrollbar synchronization, exact pane replay, canonical `codex-opencode` recovery observation, ambiguous descriptor-less rollout rejection, symlinked rollout rejection, sidebar membership, hidden-start pane visibility, authentication rollback, same-pane respawn, external token fingerprints, and private-scope canonical bindings;
- a real GTK/VTE/tmux terminal smoke proving wheel and scrollbar movement in both directions, return to bottom, `Ctrl+L`, bracketed paste, complete composer frames, sidebar-open resize equivalence to a direct application redraw, stable tmux pane identity, and preserved terminal modes;
- a real Codex-auth selector smoke proving immediate running-session switching, exact conversation continuity, same-pane identity, canonical external token ingestion, private environment inheritance, preserved cwd, and an open selected tab throughout the transaction;
- a real Tabs-pane smoke proving hidden-start mapping, high-scale left/right bounds, keyboard toggle, card navigation, synchronized multi-window visibility, and stable content geometry;
- complete CI and production validation from a short tmpfs-backed task workspace so saturated project storage cannot convert bounded process assertions into false failures;
- clean-commit reproducible double-build and strict artifact verification;
- managed install retaining 0.2.18 as rollback, GUI-only handoff, and post-install proof that persistent tmux and payload identities did not change.
