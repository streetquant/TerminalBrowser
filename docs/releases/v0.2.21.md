# T1000 0.2.21

Release date: 7 September 2026

## Decision

0.2.21 keeps the 0.2.20 managed-release and path migration history while
making the live launch contract truthful for the canonical direct-root SSD.
A production launcher admits only observed path, mount, device, filesystem, and
rotational evidence. The environment tuple is descriptive metadata and is not
a second admission gate.

## Direct-root storage contract

The attestation identifies the observed storage as direct-root with the
class non-rotational-block when every configured hot path resolves to a
non-rotational block filesystem. It does not assert ssd-cell or
CODEX_BULK_STORAGE_MASKED; those properties require independent evidence.
A desktop or systemd launch with no storage environment variables therefore
remains admissible when the path and device proof passes.

## Guarded web activation

The source-owned activation transaction publishes its durable receipt and
LATEST pointer before the first mutation. It prepares and verifies all build
artifacts before package installation, arms an independent recovery watchdog
before stopping the web units, and permits rollback from any mutation phase.
Live state validation uses SQLite backup and integrity checks, pre-existing
session identity preservation, and exact process identity observations, so
normal user activity and natural exits remain valid state changes.
