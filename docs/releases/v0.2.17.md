# T1000 0.2.17

Release date: 22 August 2026

## Decision

Promote 0.2.17 as the first managed release containing the complete durable-session recovery work and the live fixes for model-transition crashes, disappearing new-tab controls, and stale `cc-go-ulw` gateway-model inventories.

## User-visible changes

- Changing an account or refreshing a gateway-model inventory now protects the tab before replacing its tmux payload and reconnects only after the replacement is proven live.
- A stale `cc-go-ulw` tab shows a highlighted refresh icon. Activating it restarts the exact saved `--resume UUID` inside the same tmux pane and tab, then loads the current validated model cache.
- A model-change crash automatically enters bounded dead-payload recovery instead of leaving a keypress-dead terminal.
- The tab-strip `+` is a permanent notebook end action and remains visible when the tab strip overflows.
- Exiting an application returns to a shell in the same terminal. Legacy unwrapped panes receive the same behavior once, after which the shell itself is the durable payload.
- Killed-terminal history, all-window restoration, generic non-Codex recipes, and application-aware per-tab scrolling are now included in the managed package.

## Safety boundary for existing gateway sessions

A live read-only census found 86 gateway-backed tabs, 85 of which started before the current 43-model cache. They are not restarted en masse. Output capture cannot prove that an interactive composer has no unsent draft, so each stale tab is refreshed only through its explicit exact-resume action or after an actual payload failure.

The refresh action fails before mutation unless all of these match:

- the durable tmux session and pane;
- the foreground process identity;
- the exact Claude/Codex resume command;
- the saved working directory;
- the private auth scope, when present.

After mutation it must prove the same pane ID, a new PID, the same exact resume identity, and restored terminal input.

## Compatibility

The SQLite migration is additive. Legacy launch fields remain readable and are converted into canonical digest-bound recipes. Existing tmux servers and sessions are preserved during GUI handoff. Retained 0.2.11-0.2.16 managed releases remain rollback candidates under their historical release policies.

## Validation

The release is gated by:

- the complete unit/integration test inventory;
- existing GTK/VTE/tmux production smokes;
- a 30-tab real-GTK new-tab overflow regression;
- account-switch ordering and attach-recovery tests;
- a real disposable exact gateway-model refresh with same pane, new PID, retained UUID, and input echo;
- a real generic legacy-pane smoke covering clean exit to shell, non-zero recovery, `always` policy, missing-directory degradation, tmux-server recreation, and absence of optional agent-adapter calls;
- reproducible double-build, artifact verification, managed install, GUI-only handoff, rollback-capable activation, and live post-install state comparison.
